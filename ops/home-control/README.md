# Dad Radar Home Control

This toolkit lets the Dad Radar home PC accept a small, allowlisted set of remote maintenance commands through a **private** GitHub repository and a repository-level self-hosted GitHub Actions runner.

## Critical security rule

The self-hosted runner belongs only to the private `joeythepilot/dad-radar-home-control` repository. The public `joeythepilot/Dad-Radar` repository must not have this runner attached to it. Never enable the public Dad Radar repository to target the home runner.

Do not store Dad Radar `.env`, Google authorization files, provider keys, or other credentials in the control repository.

## Components

- `DadRadarRemote.ps1` is the fixed local allowlist executor.
- `Refresh-DadRadarDisplay.ps1` is retained as an interactive display-recovery helper.
- `Install-DadRadarHomeControl.ps1` installs local files/config, seeds deployment identity, and prepares the passwordless runner-service permissions.
- `home-ops.yml` is copied into the private control repo as `.github/workflows/home-ops.yml`.
- Runner custom label: `dad-radar-home`.

## Supported commands

Create issues in the private control repository using one of these exact titles:

- `[DADRADAR] status`
- `[DADRADAR] test`
- `[DADRADAR] deploy`
- `[DADRADAR] restart`
- `[DADRADAR] logs`
- `[DADRADAR] rollback`

For deploy, the issue body must be exactly:

```text
sha=0123456789abcdef0123456789abcdef01234567
```

For logs, the body may be empty or use a bounded line count:

```text
lines=200
```

The executor does not provide an arbitrary shell command.

## Low-privilege restart broker

The GitHub runner does **not** stop or start the SYSTEM-owned `Dad Radar Family Beta` scheduled task. After an exact SHA passes `npm ci` and the full local test suite, the fixed executor writes:

```text
runtime\deployed-sha.txt
runtime\remote-restart-request.json
```

The already-running SYSTEM-owned Dad Radar host watches `runtime\remote-restart-request.json`. It validates the request, removes it, and exits deliberately. The existing Windows scheduled task restarts the host using the new checkout.

The server health response reports both the running 40-character deployment SHA and a unique `instanceId`. The remote deploy is not accepted until the new process reports the requested SHA with a changed instance ID. The browser display watches the same server identity and reloads itself when the server instance changes.

This keeps restart authority inside Dad Radar's existing SYSTEM host instead of granting administrative task-control rights to the GitHub runner.

## Local Windows installation

After pulling the branch containing this toolkit, open **Windows PowerShell as Administrator** and run:

```powershell
cd C:\Users\cfijo\Dad-Radar
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\home-control\Install-DadRadarHomeControl.ps1
```

The installer verifies the Dad Radar checkout, Git, Node, npm, and the existing `Dad Radar Family Beta` server task. It installs fixed local files under `C:\DadRadarOps`, writes a non-secret local config file, seeds `runtime\deployed-sha.txt`, records known-good SHAs, and keeps an on-demand interactive display-recovery task.

For a persistent runner service, the installer also prepares the supported passwordless Windows runner identity:

```text
NT AUTHORITY\NETWORK SERVICE
```

It grants that identity Modify access to the Dad Radar checkout and `C:\DadRadarOps`, and adds the user-owned Dad Radar checkout to Git's system `safe.directory` list. The runner does not receive permission to control the SYSTEM-owned Dad Radar scheduled task.

## Private control repository

`joeythepilot/dad-radar-home-control` must remain **private**. Never put Dad Radar credentials or provider secrets in it.

The workflow lives at:

```text
.github/workflows/home-ops.yml
```

It runs only for newly opened issues whose title starts with `[DADRADAR]`. It does not check out repository code on the home PC. It passes issue title/body as data to the fixed `C:\DadRadarOps\DadRadarRemote.ps1` executor. The workflow uses a per-process PowerShell execution-policy bypass and does not change the machine-wide Windows execution policy.

## Runner setup

Install the Windows x64 GitHub Actions runner under:

```text
C:\actions-runner
```

Use:

- runner name: `dad-radar-home`
- additional label: `dad-radar-home`
- work folder: `_work`
- run as service: **Yes**
- service account: accept GitHub Runner's default `NT AUTHORITY\NETWORK SERVICE`

GitHub's Windows runner uses Network Service as its default service identity, so no personal Windows password is required. Configuring or reconfiguring the Windows service itself must be done from an Administrator PowerShell window using a fresh registration token generated by the private repository's **Settings → Actions → Runners → New self-hosted runner** page.

The runner should never be configured as a service attached to the public Dad Radar repository.

## First live checks

1. Confirm `dad-radar-home` shows **Idle** in the private control repo.
2. `[DADRADAR] status` should report checkout SHA, upstream SHA, clean/dirty state, health, running SHA, and server instance.
3. `[DADRADAR] test` should complete the full Dad Radar test suite on the physical Windows PC.
4. `[DADRADAR] deploy` should validate an exact branch SHA, run dependencies/tests, request the brokered SYSTEM-host restart, and prove the new process reports that exact SHA.
5. Reboot the PC and verify the runner service returns to **Idle** without anyone opening `run.cmd`.

## Recovery

Remote deployment refuses a dirty working tree and rejects SHAs that are not in `origin/agent/mobile-companion` history. A successful deploy records current and previous known-good SHAs under `C:\DadRadarOps\state`.

`[DADRADAR] rollback` deploys the recorded previous-good SHA through the same validation, test, restart-broker, and health-verification path.

To disable remote control immediately, stop the GitHub Actions runner service in Windows Services. Dad Radar's normal SYSTEM background server and local display remain independent of the runner.
